# The reachability matrix of the virtual gateway (tests/virtual/README.md): for each scenario, the
# settings tvgw-apply runs with, then one probe per row, what the probe must see, and the comment of
# the rule whose counter must tick. A firewall change that changes what the TV can reach changes a
# row here, so it arrives as a reviewed diff; the observed matrix of every run is in the CI artifact.
#
# source      tv (10.10.10.50), tv-foreign (the TV's link, source 10.99.0.5), tv-alias (a second
#             address in the TV subnet, 10.10.10.200: the pin's case, since TV_MAC is known) or wan
# probe       tests/virtual/agent.py: dns-udp, dns-tcp, tcp, udp, ping (port = payload bytes), gre, udp6
# verdict     pass:<where the far end saw it from: tv, wlan0, tun0>, pass (ping, gre),
#             answer:<which resolver answered: gateway, wan>, reject, drop, sent (only the counter judges)
# counter     must gain at least one packet; no other drop or reject counter may move ("-": none may)
#
# Addresses: 203.0.113.10 a web server, .20 a DoH resolver (in doh4.txt), .30 a manual block (in
# block4.txt), .53 a public resolver; 10.20.30.40 a host on the home LAN; 156.147.69.32 LG's firmware
# fallback; 198.51.100.1 the uplink router; 10.10.10.1 and 198.51.100.2 the gateway; 192.0.2.2 its tun0.
