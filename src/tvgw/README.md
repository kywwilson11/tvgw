# The tvgw package

The Python side of the gateway: parsers for every log and capture the gateway writes, the store, the hourly ingest, the queries behind the brief, `tvgw verify`, AdGuard Home as configuration, the analyst and the CLI. This page owns the module map, the rules the code follows and the ways to extend the code, for developers changing the Python code; every command, its arguments, privileges and exit codes are in [the commands](../../docs/reference/commands.md). The firewall, the capture and the units are shell and systemd, described in [deploy/README.md](../../deploy/README.md).

*The package's modules by layer: data moves one way, from the parsers through ingest into the store and out through queries to the CLI.*

- **The parsers** turn lines into dataclasses. `logtail` reads new lines from the growing logs; `conntrack`, `adguard` and `gfts` parse them; `dnsmsg` decodes the DNS answers inside AdGuard's records; `pcaps` says which captures are finished and `tshark` reads them, with `clienthello` for the hellos tshark leaves undissected and for JA4. `names` and `profile` judge the names those records carry.
- **The store.** `ingest` writes all of it into the SQLite file `db` defines. `verify` writes its verdicts and the firewall counters there too.
- **The read side.** `queries` reads the store through a connection the CLI opens and returns plain data. `cli` renders it, and `autoblock` and `analyst` build on the same `window_report()`.
- **AdGuard and the resolver.** `adguardcfg` builds AdGuard Home's configuration from the profile and the machine's rules file, which it reads through `autoblock`, and waits for the resolver with `dnsq`. `verify` asks the resolver through `dnsq` as well. (adguard) `namecheck` asks AdGuard's API about one name through `aghinstall` and names the source of the rule from `adguardcfg`'s plan. (refused) `refused` reads the query log through `adguard` and `aghinstall`, and names each refused name's source and fix through `namecheck`; `companies` gives `namecheck`, `refused` and `plain` the company behind a name. `dnsq` and `dnsgate` decode answers with `dnsmsg`.
- **The standalone modules.** `dnsgate`, `discover`, `lgwebos`, (samsung) `tizen` and `backup` are called from `cli`, and `discover` asks `tizen` whether a device another signal names Samsung is a Samsung TV. `setup` strings `discover`, `lgwebos`, `config`'s writer, the installer and `verify` together for `tvgw setup`. `lgwebos` also gives `queries` the Live Plus key (`ACR_KEY`) and `analyst` the canary's readings of the TV.

Data comes back in one place. `autoblock` writes the `auto_rules`, `judgments`, `decisions` and `auto_queue` rows, and `queries.window_report()` reads them back through `autoblock.summary()` for the brief. `autoblock` imports `queries` at module level, so `queries` and `adguardcfg` import `autoblock` inside the function that needs it; a module-level import there would be circular.

## Rules of the code

- **Parsers are pure.** A parser takes a line or bytes and returns a dataclass, a list or `None`, and reads no file and no clock: `conntrack.parse_flow()`, `adguard.parse_querylog_line()`, `gfts.parse_line()`, `tshark.parse_row()`, `clienthello.parse_record()`, `dnsmsg.decode_answers()`, `dnsgate.addresses()`, `discover.parse_leases()`. The tests feed them lines captured on the gateway.
- **`ingest.py` is the only writer of the base tables.** The tables loaded from the gateway's logs and captures, and the ingest bookkeeping, are written by `ingest` alone. Other writers own their own rows: `verify.record()` writes `verify`, `fw_counters` and the `*_version` keys of `meta`; `autoblock` writes `auto_rules`, `judgments`, `decisions` and `auto_queue`; `db.connect()` writes the schema version; (ledger) `verify` stores `gw_samples` through `ledger.record_sample()`, `ingest` writes `changes` through `ledger.ingest()`, and `judge2.shadow()` writes `judge_shadow`. Each ingest source is one transaction (`step()` in `ingest.run()`), so a failing source becomes a warning and never rolls back the others. The columns are in [the tables](../../docs/reference/data-model.md#tables).
- **Queries return plain data, and `cli` renders it.** A function in `queries.py` takes a connection and a window and returns tuples or dicts. `cli.py` prints them with `table()`, which passes every cell through `clean()`, and `--json` prints the same dicts. Text from the TV or from the servers it talks to reaches the terminal only through `clean()`, or `lgwebos.clean()` for the TV's own setting values.
- **Everything that touches the gateway is a parameter.** tshark is the `extract` argument of `ingest.run()`, `/proc` is `live`, the kernel log is `oddport_lines` and `gate_lines`, and `tvgw-flowlog`'s journal is `flowlog_lines`. `verify.check()` takes `run`, `read`, `mtime` and `resolve`; `adguardcfg.apply()` takes `control`, `ready` and `check`; `analyst.run()` takes `make_client` and `hooks`; `discover.discover()` takes the lease, neighbour and journal text and its probes; `setup.Setup` takes an `Env` of callables; `dnsgate.feed()` takes `read` and `nft`. The default is the live system, and the unit tests pass fakes: [how the code is tested without a gateway](../../tests/README.md#how-the-code-is-tested-without-a-gateway).
- **Settings are fields.** Every path and switch is a field of `config.Settings`, so a test points the tools at a temporary tree. Only the keys in `CONF_KEYS` come from the settings file, and `config.load()` refuses a near miss such as `BLOCK_QUIC=Yes` instead of falling back. The keys and their defaults are in [the settings file](../../docs/reference/settings.md).
- **Vendor knowledge is profile data.** Which names are the TV doing its job, which must never be blocked and which hosts the URL filter takes come from the profile, never from a list in the code.
- **Optional dependencies load late.** The one required dependency is `pyyaml>=6`. The `lgwebos` extra (`bscpylgtv>=0.5`) and the `analyst` extra (`anthropic>=2.0,<3`) are imported inside the functions that need them. `cli` imports `analyst`, `verify`, `adguardcfg` and the other command modules inside their `cmd_*` functions, so a read command loads none of them. The `dev` extra is `pytest>=8`, `ruff>=0.5` and `mutmut>=3.2`, and pyproject.toml sets `requires-python = ">=3.11"`.
- **Style.** ruff checks the rule sets `E`, `F`, `I`, `B`, `UP`, `SIM` and `RUF` with `line-length = 110` (pyproject.toml). `make gate` runs ruff and the unit tests as CI does: [how a change reaches the gateway](../../deploy/README.md#how-a-change-reaches-the-gateway).

## How to change or extend it

### Add a query

1. Write a function in `queries.py` that takes `conn`, `since` and `until` and returns tuples or dicts. Pass `_until(until)` to SQL, so `None` means open-ended.
2. Name flows with `FLOW_NAME` when the query reports per TLS name, so it agrees with Top upload and the category table: [naming a connection](../../docs/how-it-works/architecture.md#naming-a-connection).
3. Test it on hand-seeded rows in tests/unit/test_queries_gaps.py.
4. Show it through a command or a brief section, below.

### Add a brief section

1. Compute it in `window_report()` into a new key of `o`. The JSON output carries the key as it is.
2. Render it in `cli.render_brief()` where it belongs in the reading order. Pass every string from the TV through `table()` or `clean()`, and print the section only when it has something to show, unless an empty value is itself news.
3. Put a line that must never be true in `red_lines()`, in the order to act on it, and give it an entry in [the red lines](../../docs/use/daily-brief.md#red-lines).
4. Regenerate the golden brief and review the file it writes. On your workstation:

   ```sh
   TVGW_GOLDEN_OUT=<file> python3 -m pytest -k brief_text
   ```

5. Paste the reviewed text into `BRIEF` in tests/unit/test_cli_golden.py. A section the fixture day does not reach goes into `EVERY_SECTION` in tests/unit/test_cli_rich.py.
6. Describe the section in [the brief's sections](../../docs/reference/brief-sections.md#sections).

### Add a verify check

1. Append a `Check(name, ok, detail)` in `verify.check()`, reading the system only through the injected `run`, `read`, `mtime` and `resolve`. Write the detail with the values as read: the `Check` scrubs it when it is made, and keeps what you wrote in `raw`. tests/unit/test_verify_scrub.py runs every check over a gateway with a router, an uplink, MACs and names to leak.
2. Put a rule the check finds by its text in `verify.KEY_RULES`. tests/unit/test_deploy_lint.py checks each entry against `tvgw-apply`.
3. Script the command output in tests/unit/test_verify.py, for a pass and for a fail.
4. Describe the check in [what tvgw verify checks](../../docs/reference/verify-checks.md).

### Add a CLI command

1. Write `cmd_x(a, s, prof) -> int` in `cli.py`: `a` is the parsed arguments, `s` the `Settings`, `prof` the loaded profile, and the return value the exit code.
2. Add a subparser in `build_parser()` with `set_defaults(fn=cmd_x)`.
3. Open the store with `_ro(s)` in a read-only command, print rows with `table()`, and import a heavy or optional module inside the function.
4. Return `_usage(message)` for a usage error found after parsing, which exits 2.
5. Add a case to `GOLDEN` in tests/unit/test_cli_golden.py for a read command, and a row to [Commands](../../docs/reference/commands.md).
6. Give a command that runs on a schedule its unit: [the units](../../deploy/systemd/README.md#units).

### Show a new firewall counter in the brief

1. Give the rule in deploy/nftables/tvgw-apply both a `counter` and a `comment`: [the firewall](../../deploy/nftables/README.md).
2. Add `(comment prefix, label)` to `queries.FW_LINES`, in the order the brief shows it. The first matching prefix wins.
3. Run `make gate`. tests/unit/test_fw_lines.py reads the script and fails until every counted drop or reject has a line and every line matches a counted rule. A counted accept that is not evidence goes in that test's `ACCEPT_COUNTERS`.
4. Add the label to [Firewall held](../../docs/reference/brief-sections.md#firewall-held).

### Add an ingest source

1. Write a pure parser for one line, and test it with lines captured on the gateway.
2. Write `ingest_x(conn, s, warn)` with an `insert(lines)` closure that turns a batch of lines into rows, and feed it with `_tail(conn, "x", path, insert, warn)`. `_tail` reads `BATCH = 10_000` lines at a time (src/tvgw/ingest.py), commits each batch together with its cursor, and raises `SourceMissing` when the input does not exist. A kernel-log source uses `_ingest_kernel_log()` with an injected `lines_since`.
3. Add `step("x", ...)` in `run()`, before the pcaps step, which runs within `PCAP_BUDGET`.
4. Add the name to `SOURCES`, so the run records when it read the source, and a row count to the `rows` map in `queries.coverage()`, so Coverage can call the source `NOT ASSESSED`.
5. Add the table to `db.SCHEMA`, to `db.TABLES` for `tvgw size`, and to the list in `ingest.prune()` when its rows should age out with `DB_DAYS`. A table of decisions rather than facts gets its own setting, as `decisions` has `DECISIONS_DAYS` (registered in `config.Settings` and `CONF_KEYS`, passed to `ingest.prune()`), or is never pruned, like `auto_rules`.
6. Document the table in [the tables](../../docs/reference/data-model.md#tables).

### Add a schema column

1. Add the column to its `CREATE TABLE` in `db.SCHEMA`, for new stores.
2. Add `(table, column, type)` to `db.ADDED_COLUMNS`. `_migrate()` adds the column to an existing store at the next writer's open.
3. Raise `SCHEMA_VERSION` and add the version to the comment above it. The hardware suite checks the version a store records.
4. Test the migration on an old store, as `test_pcaps_done_gains_its_newer_columns_on_an_old_store` in tests/unit/test_ingest.py does.
5. Document the column in [the tables](../../docs/reference/data-model.md#tables).

A superseded index goes in `db.DROPPED_INDEXES`. A change to a column's type or meaning has no migration path; the schema only ever adds.

## Gotchas

- **The schema only adds.** `CREATE ... IF NOT EXISTS` runs at every writer's open, so a new table or index is safe; a changed column has no migration path ([schema changes](../../docs/reference/data-model.md#schema-changes)).
- **The AdGuard cursor key is `adguard`.** The source is `dns` everywhere else. Renaming the key would re-read the whole query log.
- **tshark exits 2 for two things.** It means "cut short in the middle of a packet", which is normal for a capture, only when stderr says so (`CUT_SHORT_TEXT` in src/tvgw/tshark.py). A file tshark could not open also exits 2, and `extract()` raises. Ingest retries such a pcap on every run, counting its failures at most once per clock hour, up to `PCAP_MAX_ATTEMPTS = 24` (src/tvgw/ingest.py): a day, however often ingest runs. Then it records the file as unreadable in `pcaps_done.error`.
- **Rule comments are an interface.** `queries.FW_LINES` and `verify.KEY_RULES` match nftables comments and rule text, and a renamed comment drops its line from the brief ([design decision 13](../../docs/design-decisions.md#13-counters-not-logs-prove-the-firewall-held)). tests/unit/test_fw_lines.py and tests/unit/test_deploy_lint.py read `tvgw-apply` and fail when either stops matching.
- **Categories follow the profile.** `hosts.category` is recomputed for every name when the profile's rules change (`meta.hosts_profile` fingerprints them), and the brief categorizes at query time, so a profile change applies to old rows too.
- **Time.** Days are local calendar days. The unit tests pin `time.time` and the time zone in tests/unit/conftest.py; code that reads the clock through `datetime.now()` escapes the pin.
- **`hosts.notes`** survives a rebuild of `hosts`, and no command writes it.
- **Settings the two sides do not share.** `WAN_GW`, `URL_FILTER_RESOLVER` and `DOH_LIST_URL` are read only by the shell scripts. `STATE_DIR`, `DB_PATH` and `REPORTS_DIR` change the Python side only: the shell side hardcodes `/var/lib/tvgw`, and `tvgw-analyze` writes its reports to `/var/lib/tvgw/reports` whatever `REPORTS_DIR` says. `TV_IF`, `TV_NET` and `GW_IP` are read by both sides. `Settings` fields outside `CONF_KEYS`, such as the log, pcap and AdGuard paths, keep their defaults on the gateway. The keys the settings table marks (reserved) are read by neither side yet: `load()` checks them, and `install.sh` and `tvgw-apply` only default the ones they are to read ([the settings file](../../docs/reference/settings.md)).
- **`tvgw autoblock list` opens the store for writing.** `cmd_autoblock()` calls `db.connect()` without `readonly` for both actions, so even the listing needs root.
- **`tvgw top-upload` counts the gateway.** It lists DNS and URL-filter traffic to `GW_IP`; the brief's Top upload leaves the gateway out.
- **Two kinds of megabyte.** `size`, `ingest` and `backup` divide by 1,000,000; `prune-pcaps` and `cli.hb()`, which prints every size in the brief, divide by powers of 1024.
- **The `hosts` counters are not the window's.** `new-hosts` and the brief's New hosts show `dns_n`, `tls_n` and `http_n`, which count every row the store holds for the name.
- **`tvgw analyst` checks less than `report`.** A malformed `--day` ends in a traceback and exit 1, not a usage error, and its usage errors begin `tvgw report: error:` because it shares `_usage()`.
- **`tvcheck` exits 0 without a Live Plus value.** Only a reading other than `off` gives 2.
- **`tvgw profile` prints the checklist only for a model,** given with `--model` or the one the TV reported.
- **Readers wait for the writer.** The store uses a rollback journal ([design decision 10](../../docs/design-decisions.md#10-a-rollback-journal-not-wal)), and `db.connect()` waits up to 60 seconds for a lock.
