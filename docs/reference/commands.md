# Commands

This page owns the `tvgw` command: every subcommand with its arguments, who may run it and its exit codes, the global options, the argument grammar and what each exit code means. It is for anyone running a command on the gateway and for developers adding one. How the code behind each command is laid out is in [the package](../../src/tvgw/README.md).

## Every command

`tvgw` is the one command (`tvgw = "tvgw.cli:main"` in pyproject.toml). The table lists every subcommand of `cli.build_parser()`, in the parser's order; the row limits are the `limit` defaults of the functions in queries.py. tvgw checks no privilege itself, except `setup`, `tv pair`, `doctor`, (site rules) `allow`, `block`, `unallow` and `unblock`, (adguard) `check` and (refused) `refused`, so a command needs whatever the files it opens need. "adm" means any member of the `adm` group, which can read the settings file and the store, so the commands that only read the store run without `sudo`. "root" means the command writes the store, reads a root-only file or changes the system. The modes are in [where it lives and who can read it](../how-it-works/privacy-and-retention.md#where-it-lives-and-who-can-read-it), and the units that run these commands on a schedule are in [the units](../../deploy/systemd/README.md#units).

## Global options

- `--conf CONF` is the settings file, `/etc/tvgw/tvgw.conf` by default. A missing file gives every setting its default. A file that exists and cannot be read stops the command, on purpose: `config.load()` never turns an unreadable file into the defaults.
- `--db DB` is the store's path, in place of `DB_PATH`.
- `--version` prints `tvgw` and the version, then exits 0.

Before any subcommand but `status` runs, `cli.main()` loads the settings and the profile `PROFILE` names. A setting value `config.load()` refuses prints `tvgw: <reason>` and exits 1. A profile that cannot be loaded whole prints `tvgw: profile <name>: <reason>` and exits 1. (depth) A settings file or a store this account may not read, and any other permission error in a command, prints `tvgw: this needs the gateway's settings: run it with sudo, or ask the computer's owner to add your account to the adm group` and exits 1, never a traceback (`NEEDS_SETTINGS` in src/tvgw/cli.py). Run as root, which may read every file of the gateway's, a permission error is something else (a sandboxed unit's limits) and is raised as it is.

## Argument grammar

| Argument | Form | Read as | Used by |
|---|---|---|---|
| DAY | `YYYY-MM-DD` | One local calendar day, midnight to midnight (`queries.day_bounds()`). | `brief`, `report --day` |
| SINCE | A number and a unit: `s`, `m`, `h`, `d` or `w` (`90m`, `2h`, `1.5d`, `7d`). | That long before now (`queries.since_epoch()`). | the six window commands, `report --since`, (refused) `refused --since` |
| SINCE | An ISO date, or date and time (`2026-10-26`, `2026-10-26T08:00`). | The gateway's local time, unless the value carries an offset. | the six window commands, `report --since`, (refused) `refused --since` |
| WEEK | `YYYY-Www` (`2026-W43`). | Monday 00:00 to the next Monday 00:00, local (`queries.week_bounds()`). | `report --week` |
| UNTIL | The forms of SINCE. | The window's end; only with `--since`; now by default. | `report --until` |

The six window commands are `new-hosts`, `retries`, `allowed`, `top-upload`, `gfts` and `tvstate`, and their SINCE defaults to `1d`. A malformed DAY, SINCE, WEEK or UNTIL is a usage error: argparse prints the usage and exits 2. `report` also exits 2 when `--until` comes with `--day` or `--week`, or when `--since` is not before `--until`.

`tvgw analyst` reads its window options itself. Its `--since` takes hours only (`6h`, at most `168h`), its `--week` must match `\d{4}-W\d{2}`, and its `--day` is passed on unchecked.

## Exit codes

- 0 means the command did its work and found nothing it reports as a finding.
- 1 means a finding (`host` never saw the name, `verify` failed a check, `adguard diff` found drift, `profile` found lint problems, `ingest` warned, (adguard) `check` found the name blocked, (refused) `refused` found a name the TV needs or one never refused before) or a failure the command names in one line. Every command that reads the store exits 1 with `cannot open <path>` when it cannot open it.
- 2 means a usage error for every command. `tvcheck` also exits 2 when Live Plus is not off, which `tvgw-analyze` reads as a warning, (depth) `status` when a check whose fix is on the TV failed, (adguard) `check` when it could not ask AdGuard Home, and (refused) `refused` when it could neither read AdGuard Home's query log nor ask it.
- (lists) `tvgw adguard apply`, `upgrade` and `service` exit 3 when they held a restart of AdGuard back because its upstreams are down, and changed nothing; `install.sh` reports it and goes on.
- (adguard) `tvgw adguard apply` exits 4 when it refused to take over an AdGuard Home tvgw did not set up, which serves other devices, and changed nothing; `install.sh` then stops with 77 and says how to go on.
- (pairing) 4 means there is no reading to take: `tvcheck` when the gateway holds no key for the TV, having asked it nothing, which `tvgw-analyze` reads as it reads 1, and `tv pair` when the profile has no LAN-API reader.
- (pairing) 4 means there is no reading to take: `tvcheck` when the gateway holds no key for the TV, having asked it nothing, which `tvgw-analyze` reads as it reads 1, and `tv pair` when the profile has no LAN-API reader or needs no pairing.
- (samsung) 5 means `tvcheck` read a Samsung profile's TV and the device answered, but not as a Samsung TV, or with a reply the reader refuses: `tvgw-analyze` keeps that reading, so the store records `rest.reply` once, and prints its `WARNING` line.
- (W12) 5 means the TV refused the gateway's key at an earlier reading: `tvcheck` asked it nothing (a refused key sent again is a prompt on the screen every hour), `tvgw-analyze` reads it as it reads 4, and `sudo tvgw tv pair` is the one way back.
